# Human 2D animation studies

## Current status: V1 rejected; V2 uses the same live client CVar

V2 is now connected to ordinary human characters through `cvar cmu.human_animations true`.
Use `cvar cmu.human_animations false` to immediately restore the original layer shaders.
The rig includes idle, walk, quiet walk, tactical walk, a heavy gait, a limp on either leg,
sprint and crawl. Short clips cover melee, gun recoil, reaching, falling and rising. Manual
timed actions loop the reach pose. Held-item poses keep the arms aligned with the live item.

Each half-cycle follows the configured footstep spacing (1.5 metres walking and 2 metres running
by default). The local player's contact poses follow the same step counter and distance remainder
used to request sound. Other characters follow that spacing using their observed movement, so their
contact phase can differ from received audio. Reparenting and large position jumps reset the
observed movement phase. The front and rear maps project the feet at different depths and shift
the hips onto the planted leg. The sprite's native rotation still drives changes in posture.

`Content.CMU/Client/HumanAnimation/CMUHumanWalkSystem.cs` registers the option locally.
The server relays confirmed melee, shot and interaction events to nearby clients. Body parts, markings, clothes and
in-hands retain their own textures. Per-layer pose lookup data is generated by `build_walk_maps.py`.
Existing female/body displacement is composed with the pose lookup. Custom shaders and unsupported
sprite sizes retain their existing rendering. Buckled, prone, unconscious, missing-leg, surrender
and exercise presentations are excluded. Disabling the option releases the temporary maps.

On 2026-11-09 the user instructed that future work must not run builds or launch the game client.
The user handles compilation and in-game review. Subsequent changes should use static checks only
unless the user explicitly changes this instruction.

## History of the offline study

### Profile clothing and cadence correction

The right arm is the near arm facing east, the left arm facing west. Sleeve, hand and exposed arm
lookups now use that same anatomical side and phase. Ankle-row pixels and boots share the rigid
foot offset. Clothing and shoes sample their constituent pieces separately from the shared RSI
atlas and composite their actual colors and alpha. A transparent pixel on one piece can no longer
overwrite a valid sample on another. Outfit geometry and texture content remain independent.

Static validation covered 1,024 lookup frames and 128 profile outfit/pose combinations: both
profile directions, two standard uniform variants, fitted/unfitted, with/without a held item,
and all eight poses. No previously covered limb pixel was exposed in these fixtures. The engine
parser accepted both shader sources. The user handles the build and visual review of cadence in game.

### Runtime lookup correction

The user reported corrupted fragments during movement. The V2 lookup RSI was missing
`load.srgb: false`: the renderer converted coordinate bytes as sRGB colors, turning neutral 128
into roughly 55 and sampling unrelated atlas cells. Both the shipped manifest and generator now
explicitly disable color conversion. The generated green channel also now follows the engine's
bottom-up UV convention: positive green selects a source pixel below the destination pixel.
Both shader variants clamp source reads to the current sprite frame and make out-of-frame
lookups transparent, including after the existing inventory/body displacement.

Read-only asset validation, with no engine, build or GPU context:

```powershell
python Tools/human_animation/check_walk_maps.py
```

The check passed for all 640 poses / 452,266 visible source coordinates, including rigid-root
direction and lit/unlit shader parity. This is not an in-game result. Restart the client before
reviewing the correction because the old RSI texture's sRGB format can remain cached.

The user tested V1 in the game on 2026-11-09 and rejected its overall visual quality.
The twelve-clip global pixel warp is withdrawn. Its prototype attachment, melee/shooting hooks,
client system, shared component/CVar, shader and tests have been removed from active game sources.
The code and original notes are preserved in `rejected/v1/` for reference only. Passing its logic
and shader compiler checks did not establish acceptable animation quality.

An already running build still contains V1 until restarted with rebuilt assemblies. Disable its
effect with `cvar cmu.human_animations false`. The new source no longer registers that option.

V2 starts with one complete eight-pose walk cycle, assembled from separate limbs. It has explicit
shoulder, elbow, wrist, hip, knee and ankle joints; a four-pose planted-foot interval; an independent
lifted return swing; and explicit far/near limb drawing order. The face, helmet and torso remain
rigid and move down at weight transfer. Original game art and licensing files are unchanged.

`studies/walk-v2.json` contains editable contact/down/passing/up poses and timing.
`render_walk_study.py` builds an offline source-resolution study with real body, clothing, armor
and boot artwork. Hidden profile sleeves/legs are reconstructed from their visible counterpart.
Detached-organ cut surfaces are covered with skin colors at joints. This reconstruction is inferred
art; it does not establish complete clothing or anatomy support.

Run from the repository root with Python, Pillow and numpy:

```powershell
python Tools/human_animation/render_walk_study.py
```

Outputs under `generated/`:

- `walk-v2.gif`: old/new comparison in four directions, plus V2 in a uniform. Both rows show one
  complete stride at the same playback cadence.
- `walk-v2.png`: a still comparison.
- `walk-v2-poses.png`: all eight profile/front poses for inspecting knees, contacts and joins.
- `walk-v2-marine.png`, `walk-v2-uniform.png`: transparent source-resolution sheets, eight frames
  across and south/north/east/west down; each cell is 40x40 including four pixels of padding.

The source-resolution sheets contain baked example outfits. Do not install them as player
sprites: doing that would discard customization, equipment and amputation state.
