Названия и пояснения находятся в FTL для ru-RU/en-US. Документы остаются русскими.

## Conflicts

1. **Звание и право отдавать приказ.** Строевой устав, «Общие принципы»,
   отделяет старшего по званию от начальника, связывая полномочия с должностью
   и цепочкой командования. `UCMJ/Crimes/AU14UCMJMinorCrimes.xml:38–39`
   определяет неподчинение шире: неисполнение законных приказов персонала
   более высокого звания. Уточнение понятия законного приказа может снять
   противоречие, однако в действующих формулировках это не объяснено.
2. **Места проверки оружия и учебного применения.** Строевой устав,
   «Случайные выстрелы», перечисляет также учебные зоны, упражнения и указания
   ответственного военнослужащего. `SOP/AU14SOPEquipmentAndPersonnel.xml:25–28`
   ограничивает обычную стрельбу стрельбищем, отдельно разрешает церемонии/
   брифинги, а учебное снаряжение — только стрельбищами. Временную безопасную
   зону при отсутствии стрельбища обозначает ВП. Учебная зона не обязательно
   является таким стрельбищем. Нужна согласованная оговорка о пределах СОП.
   Право инструктора выдавать оружие в Положении также не объясняет его
   соотношение с разрешением руководителя отдела на выдачу снаряжения этого
   отдела (`SOP/AU14SOPEquipmentAndPersonnel.xml:7`).
3. **Воинское приветствие.** Устав допускает обычное приветствие и запрещает
   прерывать экстренную работу ради церемоний. ЕКВЮ сохраняет факультативную
   статью о невыполнении приветствия после требования вышестоящего офицера
   (`UCMJ/Crimes/AU14UCMJOptionalCrimes.xml:18–19`). Это условная коллизия при
   требовании во время экстренной работы, а не общий запрет обычных приветствий.
4. **Уже существующее внутреннее противоречие СОП.**
   `SOP/AU14SOPCommand.xml:7` требует мемориал после операции, а строка 12
   объявляет его необязательным. Новые документы это противоречие не исправляют.

Все перечисленные тексты оставлены в утверждённом виде. Решение о приоритете
и согласовании норм должен принять автор нормативной базы. Запрет ненужной
стрельбы на построении не означает запрета разрешённой СОП церемониальной стрельбы.
Правило основного языка радиообмена (`SOP/AU14SOPEquipmentAndPersonnel.xml:31–37`)
сохраняется через ссылку на СОП; отсутствие его повторения в наставлении —
не отмена правила. NJP и qualification suspension остаются разными процедурами.

## Implementation mismatches

Раздел содержит исходный аудит и актуализированные положения о рекрутах и допуске
инструкторов. Эти изменения не требуют изменения seed или схемы хранения квалификаций.

| Нормативное ожидание / ограничение | Фактический код и следствие |
|---|---|
| Требования подготовки для занятия должности описаны без ограничения режимом | `QualificationSystem.Mode` отключает систему вне Восстания. В остальных режимах действуют прежние таймеры остальных профессий. Для инструкторских должностей допуск «сержант + активная аккредитация» обязателен во всех режимах без отдельного whitelist. В Восстании действуют flags Disabled/Warn/Enforce и configured role matrix. |
| Рекрут: обучение и вспомогательные задачи только внутри базы GOVFOR | Выход на задачи вне базы запрещён правилами сервера без исключений для CO и чрезвычайных обстоятельств. Корабль GOVFOR считается базой, FOB — нет. Физических блокировок движения нет; надзор и контроль учебного оружия остаются RP-процедурами. |
| «Администрация» и уполномоченные администраторы | `QualificationSystem.Authority` признаёт системным Administrator только `AdminFlags.Host`; остальные административные полномочия по названию должности не выдаются. Management ACL даёт управление отдельно. Это следует явно учитывать при назначении уполномоченных сотрудников. |
| Аккредитованный сержант-инструктор | Для официального зачёта нужны активная аккредитация нужной области и участие в текущем раунде. Код не требует, чтобы текущая должность была именно Drill Instructor/GOVFOR. Management может аттестовывать без инструкторской аккредитации. Офицер/CO не выдаются обычным инструктором. |
| Инструктор вправе требовать повторного прохождения темы | Повторную демонстрацию можно проводить вручную. Complete идемпотентен; удалить уже зачтённый пункт через CorrectProgress может только management. У инструктора нет отдельного формального состояния «пересдать». |
| Обоснованный персональный зачёт и итоговая аттестация | Система хранит автора/персонажа/должность/раунд/время. Проверка знаний остаётся RP. Поле reason не обязательно для Complete/Certify в сервисе; прямой management Grant с обязательной причиной обходит проверку чек-листа. Это административное исключение, а не доказательство экзамена. |
| Приостановление двумя офицерами / CO / администратором | Два разных действующих офицера в одном раунде/сервере с повторной проверкой первого; CO/Host единолично. Обычный Management ACL без этих дополнительных полномочий не даёт Suspend, хотя даёт Revoke/Restore. |
| Потеря допуска не должна означать автоматическое удаление персонажа | Ограничиваются последующие обычные назначения. Нет универсального pre-assignment hook в TryAssignJob/прямом DoSpawn; эти привилегированные пути и текущий персонаж не отзываются автоматически. См. существующий AUDIT.md. |
| Обжалование через Discord | Текст опубликован; интеграции, привязки аккаунта, автоматических апелляций и возврата допуска через Discord нет. |
| Статус Recruit в целом | У аккаунта без человеческого уровня UI показывает отсутствие уровня. Это не доказательство, что любая его роль, особенно синтетик, является рекрутской. См. ниже. |

Совпадающее поведение: уровни наследуются сверху вниз; приостановление нижнего
уровня прерывает доступ к зависимому верхнему; профессиональные допуски независимы;
CO отдельный и не следует из Officer; штатные подтверждения двух офицеров
не срабатывают после смены раунда; боевые права не следуют из права читать руководства;
обычный игрок не получает права менять чужую подготовку.
Изменение checklist references не меняет версий действующих сертификатов.

## Synthetic behaviour

**Current synthetic qualification behaviour:**

Реальные JobPrototype IDs из
`Content.CMU/Resources/Prototypes/CMU14/Roles/Military/GovFor/Platoon/Synthetics/AuxSupportSynth.yml`:

- `AU14JobGOVFORAuxSupportSynth`;
- `AU14JobGOVFORAuxSupportSynthRMC`;
- `AU14JobGOVFORAuxSupportSynthUPP`.

Ни одного из них нет в 93-ролевом qualification seed. При старте сервер
добавляет конкретные ненастроенные роли как `Enabled=false`, `Govfor=true`.
Qualification gate их сейчас пропускает даже без Enlisted. Их собственные
таймеры, whitelist и trait restrictions продолжают действовать. При смене
конфигурации роли оператором Enabled может стать true; вывод выше относится
к штатному seed, а не ко всем возможным сохранённым настройкам.

СОП для синтетиков (`SOP/AU14SOPDepartments.xml:49–55`) устанавливает отдельные
ограничения службы, автономности и ношения оружия. Отсутствие Enlisted не
превращает Support Synthetic в человеческого Recruit и не отменяет этих правил.
Утверждённое Положение не дополнено придуманным исключением.

**Историческая утечка миграции (устранена в PR #482):**

1. `QualificationSystem.OnSpawnComplete` записывает участие для любой назначенной роли.
2. `QualificationService.RecordParticipation` проверяет Govfor, но не Enabled и не isSynthetic.
3. `MigrationDryRun` даёт кандидату Enlisted за GOVFOR-участие последних 14 дней,
   также без фильтра Enabled/isSynthetic.
4. Для каждой из трёх реальных ролей characterization test подтверждает:
   вход разрешён без уровня; после записи участия dry-run предлагает человеческий
   Enlisted; ни вход, ни dry-run сами его не выдают. Для выдачи нужен отдельный
   management ExecuteMigration. Часы синтетика без участия сами по себе не
   включены в штатные группы сержантской/офицерской миграции.

Риск записан и воспроизведён тестом, механика не изменена. При отдельном исправлении
нужно согласовать именно критерии человеческой подготовки и обновить characterization
test: простого отключения synthetic job gate недостаточно.

**Предложение для согласования, НЕ включено в утверждённый документ:**

> Уровни рядовой, сержантской и офицерской подготовки регулируют допуск к соответствующим
> человеческим военным должностям. Допуск и порядок службы военных синтетиков определяются
> СОП и требованиями их должностей. Отсутствие человеческого уровня подготовки само по себе
> не означает рекрутский статус синтетика. Служба синтетиком сама по себе не подтверждает
> прохождение человеческой рядовой подготовки.

## Актуальное правило первоначального переноса

Одноразовый Dry Run сканирует всю историческую игровую базу. Enlisted выдаётся за
сумму **строго больше 3 часов** на человеческих GOVFOR-ролях, Sergeant — за **≥ 5 часов**,
Officer — за **≥ 10 часов**, профессиональные квалификации — за **≥ 5 часов** в своей группе.
Сержант и офицер подразумевают нижние уровни; CO не переносится. Синтетические таймеры
полностью исключены. Историческое участие за 14 дней больше не используется как основание.
Отозванные и приостановленные квалификации сохраняются. Execute требует отдельного
подтверждения и записывает маркер `govfor-training-v1`; при старте сервера выдач нет.
