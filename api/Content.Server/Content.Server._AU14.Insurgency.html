Namespace Content.Server._AU14.Insurgency

Classes

InsurgencyAuthorization

Single point of change for who may author Default factions and select Custom factions. Today this is the Host/admin flag. If a dedicated HRP whitelist flag is added later, swap the check in IsAuthorized(IAdminManager, ICommonSession) and nowhere else.

Authorization is always enforced server-side. The client editor only hides options as a convenience; every editor message re-checks here before touching the DB or applying a faction.

InsurgencyFactionApplicationComponent

Server-owned delivery state for faction effects applied to a spawned member. Kept on the mob so repeated lifecycle events are harmless while a respawned mob is handled normally.

InsurgencyFactionApplySystem

Applies a chosen FactionDefinition for the round: injects vendor sections, sets the economy conversion rate, and pushes the faction's title / description / roleplay to current INSFOR members as a briefing and a popup.

This is the single consume point for the schema. The apply runs once per faction selection, driven by ApplyFaction(FactionDefinition), never by a tick loop. State is cleared on round restart.

InsurgencyFactionSelectionSystem

GOVFOR to Default-faction matching and the server-authoritative selection path. A Default faction declares the GOVFOR platoons (USMC, TWE RMC, UPP, and so on) it may oppose; only factions that list the round's chosen GOVFOR platoon are offered, and the match is re-checked here before a faction is applied so a tampered client cannot force an unmatched faction.

InsurgencyFactionValidator

Server-side gate for untrusted faction definitions. Everything a client sends passes through here before it is stored or applied: strings are clamped to the schema caps, list counts are capped, and out-of-range numbers are pulled back into sane ranges.

This is the reusable untrusted-input seam the plan calls for. Phase 2 (Custom factions) extends it to also recompute vendor costs from the server's own balance tables and reject unknown prototype ids. It is written so the building-improvement buildsave upload can adopt the same gate. Keep the caps in FactionDefinition as the single source of truth.

InsurgencyFactionVendorComponent

Marks a vendor entity as belonging to the active INSFOR faction. When a faction is applied, InsurgencyFactionApplySystem injects the sections from the matching FactionVendorDefinition into this vendor's CMAutomatedVendorComponent. Placed on cell-kit vendors in Phase 1b; harmless before then.
