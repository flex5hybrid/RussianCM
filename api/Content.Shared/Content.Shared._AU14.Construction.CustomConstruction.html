Namespace Content.Shared._AU14.Construction.CustomConstruction

Classes

AU14MenuOverridesPrototype

AU14 construction-menu overrides, persisted as a generated prototype so the client can hide recipes the admin removed from the menu - including VANILLA recipes that the right-click recipe editor never sees (it only tracks recipes IT generated). The server writes a single instance of this into Resources/Prototypes/_AU14/CustomConstruction/Generated/Overrides/; on the next restart the client loads it and the construction-menu presenter skips any recipe whose construction id is listed here.

DeleteSpawnlistEvent

Client → server: delete a whole spawnlist - every generated recipe (construction entries and tiles) filed under it is removed from disk, the database, the server's loaded prototypes, and hidden from open menus. Destructive; the window arms a confirm delay before sending. Re-validated server-side.

HideConstructionRecipeEvent

Client → server: hide a construction-menu recipe by its construction prototype id (the "Remove Item" button in the menu detail panel). Works for ANY recipe, including vanilla ones the right-click editor can't track: the server records the id in a generated overrides prototype so the menu skips it (applies next restart; the acting admin's client also hides it immediately for this session). Re-validated server-side.

OpenCustomConstructionChooserEvent

Server → client: the picked entity already has recipe entries, so show a chooser to change/remove an existing one or add a new recipe (instead of jumping straight into the add editor).

OpenCustomConstructionEditorEvent

Server → client: open the construction-menu editor window for an entity. Sent when a permitted admin uses the world "Add to / Change Recipe" verbs, or in response to the in-menu admin button.

OpenCustomLatheEditorEvent

Server -> client: open the lathe editor, with the recipes already added (so they can be removed).

OpenCustomTileEditorEvent

Server -> client: open the TILE editor (the "Tiles" sibling of the Construction Items Editor). Lets a permitted admin add a tile to the construction menu; the server turns the chosen tile into a buildable tile-applier entity automatically. Sent in response to RequestOpenCustomTileEditorEvent.

OpenDbSavePreviewEvent

Server → client: the scrollable human-in-the-loop confirmation shown before a save is committed. Lists, line by line, exactly which files and database rows the save would write (built by the SAME validation pass that the real save uses, so what you confirm is what happens). The client re-sends the original submit with Preview = false on confirm, or drops it on cancel.

OpenMassConstructionEditorEvent

Server → client: open ONE recipe editor for a whole batch of entities. Editor carries the standard editor payload (spawnlists/categories/default steps) keyed off the first entity; ProtoIds is the validated batch the client must echo back in the mass submit.

OpenSpawnlistDeleteEvent

Server → client: opens the Spawnlist Delete window with every spawnlist that currently has generated recipes (construction entries AND tiles), plus how many recipes each holds so the admin sees the blast radius before confirming.

RemoveCustomConstructionEntryEvent

Client → server: remove an existing recipe entry (from the chooser). Re-validated server-side.

RemoveCustomConstructionGroupEvent

Client → server: bulk-remove EVERY generated recipe in a spawnlist (and category, if set). Destructive, so the editor gates it behind an "include all entities" acknowledgement and a 3-second warning before sending.

RemoveCustomLatheRecipeEvent

Client -> server: remove a previously-added lathe recipe (by its generated recipe id).

RequestOpenCustomConstructionEditorEvent

Client → server: open the editor for an entity chosen from the in-menu "Construction Items Editor" utility. The server re-validates admin permission before opening (the client also pre-checks so non-admins get an immediate popup instead). When EntryKey is set, the server opens the editor directly for that existing entry (Change Recipe); empty opens the add/chooser flow.

RequestOpenCustomLatheEditorEvent

Client -> server: the admin pressed the in-menu "Lathe Editor" button. The server re-checks permission.

RequestOpenCustomTileEditorEvent

Client -> server: the admin pressed the in-menu "Tiles Editor" button. The server re-checks permission.

RequestOpenMassConstructionEditorEvent

Client → server: the admin picked a batch of entities in the "Mass Entity Editor" selector and wants the recipe editor opened for the whole batch. The server re-validates permission (and the id list) and replies with OpenMassConstructionEditorEvent.

RequestOpenSpawnlistDeleteEvent

Client → server: open the Spawnlist Delete tool (gated by the "spawnlistdelete" tool permission, re-validated server-side). The server answers with OpenSpawnlistDeleteEvent.

SubmitCustomConstructionEditorEvent

Client → server: the admin confirmed the editor. The server re-validates permission, writes the generated prototype file, logs the action, and pops up the result.

SubmitCustomLatheEditorEvent

Client -> server: add a print recipe to one of the CM lathes. The server validates the result entity, writes the latheRecipe, and rebuilds the lathe's recipe pack (applies next restart).

SubmitCustomTileEditorEvent

Client -> server: the admin confirmed the tile editor. The server validates, writes the generated tile-applier + recipe, and pops up the result.

SubmitMassConstructionEditorEvent

Client → server: the admin confirmed the mass editor. One recipe (spawnlist/category/steps) is applied to EVERY entity in ProtoIds - each gets its own independent entry file, exactly as if it had been added one-by-one, so any single one can still be changed or removed individually afterwards.

SubmitMassTileEditorEvent

Client → server: the Mass Entity Editor's TILES mode was confirmed. One material cost / category is applied to every tile in TileIds - each becomes its own independent generated tile recipe, exactly as if added one-by-one through the Tiles Editor.
