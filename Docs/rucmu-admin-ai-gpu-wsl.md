# Локальная GPU-проверка генерации, 2026-10-14

Это отдельный, явно одобренный пользователем тест на WSL. CPU-профиль production
сохраняется. Для цели 1–3 секунды требуется подходящая свободная GPU; одно CPU
не обеспечивает эту задержку для всех черновиков. Полную приёмку RuCMU и трёх Squad
этот тест не заменяет.

## Фактически проверенная конфигурация

- RTX 3060 Ti, 8192 MiB, WSL Ubuntu 26.04.1, драйвер Windows 610.88.
- Qwen3-4B-Instruct-2507-Q4_K_M: тот же файл, SHA256
  `2fde00ce69dd4899c70d020845e2638353015bba0fdf161b3eb965f2bca4464e`.
- llama.cpp b11429 / d81235049, официальный CUDA 12.8 build.
- Архив приложения: SHA256
  `b13c64b9224d3c89d9993945d70cc21177ad00178c21b8d34237e3bc139834f1`.
- Архив CUDA runtime: SHA256
  `f4ab593e31507320b121f2cb21791f4c72420a2483d3df8bf2ca1a97d04e6845`.
- Установленный CUDA llama-server: SHA256
  `5a2b208943ca04915d380824f3fcf79f1708b22d8157e4db3cb18b3e52b8b8cc`.
- Один слот, один CPU, RAM high/max 3/4 GiB, swap 0, UDS, PrivateNetwork,
  отдельный непривилегированный пользователь. Модель не получает команд/инструментов.
- CUDA0, все слои на GPU, q8 KV, flash attention, context 4096,
  batch/ubatch 512, cache-ram 0, ctx-checkpoints 0. `fit off` исключает
  незаметный переход части модели на CPU при недостатке VRAM.

Артефакты скачаны отдельно оператором, не при сборке/старте/во время игрового запроса:
[официальный релиз](https://github.com/ggml-org/llama.cpp/releases/tag/b11429).
Бинарники, модель и локальные настройки не входят в Git.

## Результат

Измеритель компилирует настоящие AIInferenceProtocol, UdsAIInferenceClient,
AIDraftPrompt и AIRuleKnowledgeBase. Он использует 259 опубликованных документов /
5728 фрагментов, тот же бюджет 2300 символов и 128 output tokens. Ответы действительно
генерируются моделью и проходят штатную проверку `finish_reason=stop`; выдержка,
шаблон, частичный текст и timeout не засчитываются как успешная генерация.

30 последовательных запросов: десять разных искусственных вопросов, три прохода;
в последнем добавлен предыдущий контекст. Вопрос «Привет помогите» предоставлен
пользователем; реальные приватные логи/заметки в измеритель не передавались.

| Вариант | p95 | Максимум | Более 3 s |
| --- | ---: | ---: | ---: |
| GPU, q8 KV, batch/ubatch 256/128, прежний длинный ответ | 7,60 s | 8,51 s | 27/30 |
| GPU, FP16 KV, batch/ubatch 512, прежний длинный ответ | 5,86 s | 6,10 s | 23/30 |
| FP16/512, исправленный контекст, до 20 слов, до открытия двух клиентов | 2,16 s | 2,24 s | 0/30 |
| q8/512, до 20 слов, два клиента InGame | 0,60 s | 0,61 s | 0/30 |
| Повтор q8/512, два клиента InGame | 0,62 s | 0,66 s | 0/30 |
| q8/512, 3975 символов контекста, два клиента InGame | 0,69 s | 0,80 s | 0/30 |

Первый компактный FP16-вариант: 30 Success, 0 invalid/timeout; p50 1,57 s. «Привет помогите»:
1,38 s, сгенерированный ответ: «Привет! Помогу — уточни, пожалуйста, о чём тебе нужна
помощь?» Его предмет больше не подменяется нерелевантным лором VAI.

Первый короткий запрос первоначального CUDA-профиля занимал 12,08 s; прогретый —
0,65 s. Это не было выдано за скорость полноценных запросов. Перед доступом клиентов
нужно завершить загрузку/прогрев, затем проверить полный контекст. Результат —
измеренная задержка этих коротких черновиков, не гарантия произвольного объёма,
очереди, холодного запуска, чужой нагрузки GPU или сетевого RTT.

При повторе с двумя тестовыми клиентами и оставшимся дополнительным SS14.Loader /
записью-оверлеями GPU предел нарушился: первый запрос TimedOut 45,01 s, второй
Success 26,68 s. Прогон остановлен; это не успешная приёмка скорости с игровыми
окнами. По Windows GPU counters обнаружена конкурирующая нагрузка, чужие процессы
не останавливались. Этот отрицательный результат сохраняется в
`gpu-benchmark-two-clients.log`; исходные 30/30 не заменяют эту проверку.

Короткий повтор FP16 с двумя клиентами: 3/3 TimedOut (диагностический предел 10 s).
После закрытия только двух собственных клиентов: 3/3 Success, 0,99–1,60 s;
наблюдаемая VRAM снизилась с 7605 до 5962 MiB, загрузка GPU оставалась 99%.
Это указывает на чувствительность к доступной видеопамяти. Затем q8 KV-кеш
уменьшил память worker; оба клиента открыты снова, прошли InGame и администратор
получил права. Счётчики фоновой нагрузки также изменились: GPU после полного
прогона 17%, VRAM 7632 MiB. Весь выигрыш нельзя приписывать одному q8-кешу:
это реальные прогоны при разных наблюдаемых условиях, не изолированный A/B-тест.
Дополнительные SS14.Loader/Discord Clips не останавливались агентом.

Итоговый q8/512: две серии по 30 запросов с источниками и третья серия из 30
запросов с 3975 символами входа в стандартном лимите 4096; в ней весь бюджет
занимал искусственный предыдущий контекст, без источников. Все 90 ответов —
Success, без invalid/timeout, max 0,80 s. Последний набор проверяет задержку
длинного входа, не качество ответа на механику без источников. Это измерение
production UDS client + протокола + модели; игровой handler/очередь, сетевой RTT
и отрисовка UI в длительность не включены. Полный ручной E2E нового GPU-профиля
ещё требует подтверждения игроком. «Привет помогите» в первой итоговой серии:
0,51 s, полностью сгенерированная просьба уточнить вопрос.

## Развёртывание теста и откат

1. Использовать только отдельные проверенные локальные CUDA-артефакты в
   `/opt/rucmu-ai/gpu/bin`, root-owned 0755 directory; binary 0555, libraries 0444.
2. Установить отдельный `worker-cuda-wsl-test-preflight.sh` как
   `/opt/rucmu-ai/gpu/bin/worker-preflight.sh` (root/0555). Общая проверка CPU
   не заменяется. GPU preflight проверяет /dev/dxg, CUDA0, SHA256/version и параметры.
3. Заполнить `worker-cuda-wsl-test.env.example`, установить его как
   `/etc/rucmu-ai/worker-gpu-test.env` с root ownership/0640.
4. Скопировать `rucmu-ai-worker-cuda-wsl-test.service.example` в отдельный
   `/etc/systemd/system/rucmu-ai-worker-gpu-test.service` (root/0644).
   Не включать автозапуск. В момент смены worker не должно быть активной генерации.
5. Оператор останавливает CPU-worker, выполняет daemon-reload и вручную запускает
   GPU-worker. Сокет один, одновременно оба worker не запускаются. Проверить Ready,
   выполнить фиксированный model-smoke и проверить полный контекст до ручного теста.
6. Откат: остановить GPU-worker, вручную запустить прежний CPU-worker.
   Обычный ахелп сохраняется и при недоступности обоих.

GPU-доступ является отдельным изменением изоляции: PrivateDevices=no,
DevicePolicy=closed, DeviceAllow=/dev/dxg rw. Это явно одобрено только для локального
WSL-теста. Другие устройства, сеть, игровые файлы и административные действия не
разрешаются. Эти device paths нельзя копировать на production Linux: необходим
отдельный аудит GPU/драйвера/устройств и нагрузки четырёх игровых серверов.

MemoryMax не ограничивает VRAM. Требуется свободная видеопамять под модель и буферы.
Тестовые клиенты используют штатные `display.max_fps=60` и
`res.texturepreloadingenabled=false`, чтобы не загружать все игровые текстуры сразу.
Это параметры только тестового запуска, не изменения движка или production-клиента.

Локальные доказательства находятся в ignored `.codex-build/admin-ai`:
`gpu-benchmark-compact-20.{log,json}`, `gpu-benchmark-{q8-128,f16-512}.{log,json}`,
`gpu-benchmark-compact-q8-two-clients{,-repeat}.{log,json}`,
`gpu-benchmark-max-context-two-clients.log`, `gpu-benchmark-max-context.json`,
`latency-{boundary,server,linux-server}*`. Измеритель не входит в игровой процесс.
