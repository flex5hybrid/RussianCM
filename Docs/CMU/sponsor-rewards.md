# Награды спонсорам

В игровом окне «Награды спонсора» появилась вкладка «Персонализация».
Настройки общие для аккаунта. Предметы выдаются при следующем входе в раунд,
а облик и цвет обычного призрака обновляются после сохранения.

| Уровень | Награды |
| --- | --- |
| Колонист, 200 ₽ | Существующий цвет OOC, список спонсоров с возможностью скрыть своё имя |
| Новобранец, 300 ₽ | Цвет призрака и пять обликов с предпросмотром |
| Боец, 500 ₽ | Существующие имена снаряжения, надпись на штатном жетоне до 60 символов, три декоративные нашивки |
| Штурмовик, 900 ₽ | Существующая персональная фигурка, согласованное описание до 200 символов, восемь базовых плащей |
| Разведчик, 2 000 ₽ | Лобби-сообщение, все 16 плащей, золотая/серебряная/красная окантовка и три эмблемы |
| Лидер восстания, 15 000 ₽ | Все предыдущие награды, выдача согласованного индивидуального косметического предмета |

Роль Discord, закрытый чат и ранние публикации управляются в соответствующих
сервисах. Этот код не меняет их настройки и не публикует тексты на Boosty.
Существующий скрытый уровень «Командир ячейки» остаётся совместимым с новыми
наградами, но больше не создаётся командой заполнения текущих уровней.

## Доступ и окончание подписки

Сервер проверяет текущий уровень перед сохранением нового выбора и перед
выдачей. Настройки находятся в `cmu_sponsor_preferences`, отдельно от
`rmc_patrons`, поэтому сохраняются даже при удалении записи о подписке.
Недоступные сохранённые варианты не выдаются. Уже выданные в текущем раунде
обычные предметы остаются в мире; изменение подписки применяется к следующей
выдаче. Цвет и облик призрака сбрасываются при обновлении статуса подписки.

Плащ занимает слот шеи. Если он занят штатной экипировкой, плащ выдаётся в
рюкзак, руку или кладётся у ног. Нашивка крепится к подходящей форме;
при отсутствии подходящей формы выдаётся таким же способом. Жетон сохраняет
имя, должность, доступы и IFF; добавленная надпись видна при осмотре.
Предметы выдаются гуманоидам с компонентом Marine; ксеноморфам они не выдаются.
Особый облик административного призрака сохраняется.

Фигурки, которые уже добавлены в ресурсы проекта, остаются в общей случайной
коллекции после окончания подписки владельца. Личная выдача фигурки требует
действующего уровня с этой наградой. Создание спрайта фигурки остаётся работой
команды: предпросмотр показывает уже опубликованный прототип.

## Согласование текстов

Команда `cmusponsor` доступна хосту. Сначала прочитайте актуальный черновик:

```text
cmusponsor review "Nickname"
cmusponsor approve "Nickname" figurine "Точный текст просмотренного описания"
cmusponsor approve "Nickname" lobby "Точный текст просмотренного сообщения"
```

Описание фигурки и лобби-сообщение одобряются только при совпадении с актуальным
черновиком. Проверка повторяется при записи в базу, поэтому изменённый во время
проверки текст не получает чужое одобрение. Старое одобренное описание фигурки
остаётся опубликованным, пока новое не согласовано. Пустое описание можно
согласовать для удаления добавленного текста.

Изменение лобби-сообщения снимает одобрение. При каждой публикации сервер
выбирает сообщение из одобренных текстов действующих спонсоров; прошлый автор
исключается, если доступен другой. При миграции уже публиковавшиеся сообщения
сохраняют доступ до следующей правки.

## Индивидуальные предметы

После проверки трёх оплаченных месяцев верхнего уровня команда согласовывает
один косметический заказ. Проверка истории платежей выполняется вручную:
имеющаяся игровая база хранит текущий уровень, а не историю оплаченных месяцев.
Повторные заказы согласовываются отдельно; код не создаёт ежемесячные заказы.

Добавьте прототип предмета в ресурсы CMU с компонентом:

```yaml
- type: CMUSponsorCustomItem
  owner: 11111111-1111-1111-1111-111111111111
```

После проверки спрайтов, лицензии и отсутствия преимуществ в игровых
характеристиках назначьте прототип конкретному владельцу:

```text
cmusponsor custom "Nickname" CMUApprovedCosmeticPrototype
cmusponsor custom "Nickname" clear
```

Произвольный прототип без метки владельца назначить нельзя. Выдача требует
действующего верхнего уровня. Один аккаунт хранит один назначенный предмет;
спрайт и прототип не создаются автоматически.

## Проверка

```text
dotnet test Content.Tests/Content.Tests.csproj --filter FullyQualifiedName~CMUSponsor
dotnet test Content.IntegrationTests/Content.IntegrationTests.csproj --filter FullyQualifiedName~CMUSponsorIntegrationTests
dotnet run --project Content.YAMLLinter/Content.YAMLLinter.csproj
```

Для ручной проверки на тестовом сервере: создать уровни через `rmcboosty seed`,
выдать каждый из шести уровней, проверить сохранение и повторный вход в раунд,
затем понизить уровень при открытом окне. Проверить жетон и нашивку, занятый
слот шеи, все направления анимации плаща, согласование нового текста и
отклонение запроса косметики, недоступной текущему уровню.
